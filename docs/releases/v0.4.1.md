# Codex Gateway v0.4.1 (Preview)

This pre-release expands Codex Gateway's compatibility layer, multi-repository routing, runtime self-management, and standalone binary validation. It remains a preview because the dynamic Codex protocol and workspace compatibility surfaces are new and should continue to receive broad real-world coverage before becoming the latest stable release.

## Highlights

- Generate discoverable `codex_rpc__...` tools from the installed Codex app-server JSON Schema, with experimental-schema fallback, executable fingerprinting, persistent caching, and automatic refresh after Codex binary changes. The tested Codex CLI 0.153.1 installation exposed 154 request methods. This is an inventory count, not a claim that every method was invoked.
- Keep the ten-action public MCP interface compact while supporting request-scoped repository selection. `workspace_call`, `workspace_batch`, the top-level workspace selector, and the reserved `__gatewayWorkspace` compatibility argument all preserve existing connector schemas.
- Make `gateway_info` a one-call routing diagnostic by reporting compact discovered workspace names/selectors, runtime identity, grants, Codex protocol status, and the cached-schema invocation pattern.
- Buffer Codex notifications and server requests, expose pending-request responses, preserve structured errors, and limit overload retries to operations classified as reads.
- Add ranked tool discovery, deduplicated and cached skill discovery, paginated file listing, and a separate `exec_readonly` command surface.
- Normalize Apple tool resolution for XcodeBuildMCP and Codex child processes, avoiding stale user-local `xcrun` shims. Probe simulator readiness with a real command and allow XcodeBuildMCP to consume only its managed build-artifact paths outside the selected repository.
- Expose live runtime identity and support credential-free `handover --restart-existing` for an existing managed profile.
- Fix standalone executable startup by embedding source identity at build time. Compiled handover workers invoke the embedded CLI rather than nonexistent bundled source paths.

## Validation

At release preparation on the development Mac:

- `bun run verify`: TypeScript checking, portable tests, and strict doctor passed.
- `bun run test:live`: all installed-tool integration tests passed on the configured development machine.
- `bun run build` and `bun run smoke:binary`: passed. A copy of only the executable, outside the source checkout, served MCP initialization, the eleven-tool catalog, and runtime identity with the expected source fingerprint.
- GitHub Linux CI passed for the release commit.
- The macOS ARM64 executable uses an ad-hoc signature. It is not Apple Developer ID signed or notarized.

Portable CI runs the build and isolated executable smoke check. Run `bun run test:live` on a suitably configured Mac for installed Codex/Xcode integration checks; portable CI intentionally does not assume those host tools exist.

## Known limitations and operational boundaries

- Dynamic discovery cannot grant model quota, authentication, desktop-host privileges, or operating-system permissions.
- The standalone app-server surface is not identical to every Codex Desktop UI control or host-managed connector. Newly discovered methods still require appropriate permissions and, where applicable, explicit confirmation.
- Gateway path checks and command classifications are defense in depth, not a general-purpose operating-system sandbox. Approved general-purpose commands can perform operations permitted to their process. Use trusted local clients and repositories and retain the Codex sandbox for Codex execution.
- Xcode, simulator runtimes, Codex, and XcodeBuildMCP are external prerequisites and are not bundled by this asset.
- Runtime keys, tunnel profiles, personal workspace contents, and downstream project-specific validation data are not shipped in this repository or release asset.

## Installation and assets

The attached `codex-gateway-v0.4.1-darwin-arm64.tar.gz` contains the compiled macOS Apple Silicon CLI and public project documentation. Verify it against the attached `.sha256` file before extracting. Source archives for this tag are also available from GitHub. No npm registry publication is performed by this release.

Existing source installations can update to the tag, run `bun install --frozen-lockfile`, and validate with `bun run verify`. Existing runtime profiles and keys remain local; do not paste credentials into issue reports.
