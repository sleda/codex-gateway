# Codex Gateway v0.5.0 (Preview)

This preview adds durable, project-independent Run management without expanding the existing eleven-action public MCP interface. It does not depend on a particular application, framework, or downstream repository.

## Highlights

- **Durable workspace runs:** ten progressively discovered tools cover Run creation, listing, reads, task plans, transitions, task updates, evidence, checkpoints, resume context, and events. Existing Web goals and cached connector routing remain compatible.
- **Explicit execution state:** dependency validation, cycle detection, deterministic ready tasks, acceptance gates, and terminal-state protection prevent invalid metadata transitions. A Run is a persisted coordination record, not a background agent.
- **Transactional persistence:** workspace-scoped SQLite stores snapshots, event history, and idempotency receipts together. Expected revisions reject stale writes; idempotency keys make repeated metadata requests safe across process restarts.
- **Trust boundaries:** writes still require operator opt-in and confirmation. State and artifact paths are checked; unsafe links and corrupt state fail closed. Evidence is labelled caller-reported and never presented as Gateway-attested execution.
- **Compatibility and runtime fixes:** include the read-only router and host-action diagnostics added after v0.4.1, narrowest-grant profile selection, and removal of stale session IDs for completed commands.
- **Optional desktop bridge:** expose Computer Use only when the installed Codex cua_repl runtime is connected. Desktop access remains host-dependent and requires existing Codex mutation permission and explicit confirmation.

## Operational boundaries

- Run evidence is caller-reported, not independently verified command output.
- Checkpoints only retain metadata; they do not snapshot or roll back workspace files.
- A Run does not launch model turns, schedule autonomous work, or cancel external workers when blocked or cancelled.
- Append-only API history is not cryptographic tamper-proofing. State has no automatic retention policy.
- The optional Computer Use bridge requires the installed host runtime, authentication, and operating-system permissions; this preview does not claim portable desktop availability.
- General-purpose command approvals and Gateway path checks are not a replacement for an operating-system sandbox. Use trusted clients and keep appropriate execution permissions.

## Installation and assets

The attached codex-gateway-v0.5.0-darwin-arm64.tar.gz contains the compiled macOS Apple Silicon CLI and public documentation. Verify the archive with the attached SHA-256 file. The executable is ad-hoc signed, not Apple Developer ID signed or notarized. Linux users can build from the tagged source; no Linux executable is attached.

Source installations can check out v0.5.0, run bun install --frozen-lockfile, and validate before restarting their existing runtime. Local profiles, credentials, workspace contents, and Run databases are not included. This GitHub release does not publish to npm or deploy any downstream application.

See [Durable workspace runs](https://github.com/sleda/codex-gateway/blob/v0.5.0/docs/runs.md) for exact tool payloads, lifecycle rules, and security limits.
