# Codex Gateway v0.5.1

This hotfix restores reconnect compatibility for ChatGPT apps that were created against Codex Gateway's original published MCP action snapshot. It remains project-independent and does not couple the Gateway to Navly or any downstream repository.

## What changed

- The public MCP surface is pinned back to the original ten actions and their published input schemas.
- v0.5 capabilities such as durable Runs, workspace routing, dynamic Codex RPCs, and Computer Use remain discoverable behind `tool_search` and executable through the existing `tool_call` router.
- The later `read_call` action is no longer advertised publicly. A hidden compatibility handler remains for cached callers, so removing it from `tools/list` does not delete internal safety behavior.
- Request-scoped workspace selection still works with `__gatewayWorkspace` inside the existing `arguments` object, avoiding a public schema change.
- Gateway startup instructions now require checking `gateway_info` and mutation discovery before claiming the connection is read-only.

## Why

Published ChatGPT apps can retain a frozen snapshot of MCP tools and inputs. Adding or changing public actions after publication can make reconnect or action refresh fail, especially where the product does not expose an action-refresh control. Codex Gateway now treats the original ten-action schema as a compatibility boundary; future capabilities should be added behind discovery unless a deliberately new app contract is introduced.

## Validation

- Portable Gateway and Run integration tests include an exact public-schema regression.
- TypeScript checking, the full portable test suite, compiled binary build, and isolated binary smoke validation are required before release.
- Live Codex/Xcode/Computer Use tests remain opt-in because they depend on the host installation.

## Operational boundary

This hotfix does not loosen write, command, sensitive-file, Codex mutation, or Computer Use permissions. A write still requires the local opt-in and the target action's confirmation. It also does not create a new tunnel or replace credentials.
